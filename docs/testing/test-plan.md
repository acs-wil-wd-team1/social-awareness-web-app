# Test plan

**Status:** Draft for team and Tester review

## Purpose

Confirm that the four Stage 2 features work correctly and provide evidence for the Prototype Document and Design Document.

## Stage 2 areas

- Campaign homepage
- Registration
- Login
- Logout
- Responsive layout
- Accessibility
- Frontend and backend integration

## Types of checks

### Suggested developer checks

- Component and integration tests
- Form validation
- Loading, empty and error states
- Build and lint checks
- Authentication-state behaviour
- API response handling

### Tester checks

The Tester role will confirm the formal browser, automation and performance-testing approach.

Meeting 1 recorded Selenium and Cypress as initial testing choices.

## Test environments

Testing should record:

- browser
- device or viewport
- application version or commit
- frontend data source
- backend version when connected
- date
- person performing the check

## Defects

Defects should be recorded in Jira with the steps to reproduce, expected result, actual result, evidence, severity, fix reference and retest result.
